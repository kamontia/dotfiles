# Claude Code、Codex、Antigravityの監督設計

## 目的

Claude Codeを開発作業の司令塔とし、Codexへの委譲が完了通知の取りこぼしやハングによって停止しない構成を作る。

Claude Codeの通常処理にはSonnetを使い、難しい判断が必要な場合だけOpusへ問い合わせる。

Codexには実装とコードレビューを委譲し、Antigravity CLIには実装完了後のE2Eテストとブラウザ検証を委譲する。

モバイルではClaudeアプリから実行中のClaude Codeセッションを操作する。

Codex AppはCodexスレッドの詳細確認に使えるが、正常な完了回収に必須とはしない。

## 対象範囲

この設計では、Claude Codeから起動するCodexジョブの監督と、実装完了後に行うCodexレビューとAntigravity検証の並列実行を扱う。

Claude CodeのサブエージェントとOpusへの問い合わせはClaude Code自身が管理するため、新しい監督処理の対象外とする。

CAOは準備中であるため、実行経路にも依存関係にも含めない。

既存のCAO設定は変更しない。

本番環境への操作、`git push`、自動デプロイ、外部サービスへの公開は対象外とする。

## 構成

Claude Sonnetを唯一のオーケストレーターとする。

既存のClaude Code用 `codex-advisor` スキルをchezmoiの管理対象へ移し、監督機能を追加する。

監督機能は公開CLIだけを呼び出し、公式Codex Claude Codeプラグインの内部スクリプトには依存しない。

```text
Claude Sonnet
    ↓
codex-advisor
    ├─ モデルとエフォートの決定
    ├─ 子プロセスの起動
    ├─ 状態のポーリング
    ├─ 完了結果の明示的な回収
    └─ 異常時の診断情報の返却
        ├─ codex exec
        ├─ codex exec review
        └─ agy --print
```

`codex-advisor` はタスクの実装内容を独自に決めない。

実装方針、結果の採否、ハング疑い時の次の操作はClaude Sonnetが決める。

## 実行モード

`codex-advisor` は次の実行モードを提供する。

- **`advise`**：設計判断や実装方針をCodexへ相談する。
- **`implement`**：Codexに実装とテストを依頼する。
- **`review`**：Codexにコードレビューを依頼する。
- **`verify-parallel`**：CodexレビューとAntigravity検証を並列実行する。
- **`status`**：保存済みの実行状態を読み、結果または診断情報を返す。

`implement` の完了後に `verify-parallel` を実行する。

実装対象が完成する前にE2Eテストを開始しても検証対象が確定しないため、実装とE2Eテストは並列化しない。

CodexレビューとAntigravity検証は同じ完成済みの変更を独立して確認できるため、並列化する。

## モデルルーティング

Claude Sonnetはタスクごとに `intent`、`complexity`、`risk` を判定する。

`codex-advisor` はその分類を許可済みのモデルとエフォートへ決定論的に変換する。

Sonnetが任意のモデル文字列を直接渡す構成にはしない。

| タスク | モデル | エフォート |
|---|---|---|
| 単純な調査または機械的な小修正 | `gpt-5.6-terra` | `low` |
| 通常の実装またはバグ修正 | `gpt-5.6-terra` | `medium` |
| 複数箇所に及ぶ実装または原因不明の障害 | `gpt-5.6-terra` | `high` |
| 設計判断、並行処理、認証、データ損失リスクの調査 | `gpt-5.6-sol` | `high` または `xhigh` |
| 通常のコードレビュー | `gpt-5.6-sol` | `high` |
| 重大リスクを対象にした厳格なレビュー | `gpt-5.6-sol` | `xhigh` |

Antigravity検証には `Gemini 3.5 Flash (High)` を既定で使う。

軽量な検証へ切り替える必要が生じるまでは、Antigravityのモデルを動的選択の対象に含めない。

実際に選んだモデルとエフォートは、各実行結果へ記録する。

## 状態管理

監督処理は、子プロセスの状態とClaudeへ返す監督結果を分けて管理する。

子プロセスの状態は `queued`、`running`、`completed`、`failed` のいずれかとする。

```text
queued
  ↓
running
  ├─ completed
  └─ failed
```

`completed` を検出した場合、非同期通知の有無にかかわらず保存済みの出力から結果を取得する。

`failed` では、終了コード、標準エラー、最後に確認できた進捗をClaudeへ返す。

監督結果は `success`、`partial`、`failed`、`timed_out`、`stale` のいずれかとする。

`stale` は、子プロセスが `running` のまま、Codexの状態とログが一定時間変化していない場合に返す。

`timed_out` は、子プロセスが `running` のまま、監督処理の待機上限へ達した場合に返す。

無出力だけではハングを断定できないため、`stale` は「ハング疑い」として扱う。

監督処理は `stale`、`timed_out`、`failed` のいずれでも、子プロセスを自動キャンセルまたは自動再実行しない。

`stale` または `timed_out` を返した後も、子プロセスの状態は `running` のまま保存する。

後続の `status` は子プロセスを再確認し、終了していれば `completed` または `failed` へ更新して結果を回収する。

Claude Sonnetがプロセス状態、ログ、変更ファイルを確認し、次の操作を決める。

## タイムアウト

初期値は次のとおりとする。

| 対象 | 無進捗の判定 | 実行時間の上限 |
|---|---:|---:|
| Codex実装 | 10分 | 45分 |
| Codexレビュー | 10分 | 30分 |
| Antigravity検証 | CLIの終了状態を使用 | 15分 |

タイムアウト値は環境変数で上書きできるようにする。

Codexの状態確認は短い間隔で行うが、ポーリング間隔を利用者へ通知する必要はない。

Antigravityには `--print-timeout` を指定し、独自の無進捗判定は設けない。

## 並列実行

`verify-parallel` はCodexレビューとAntigravity検証を同じ監督プロセスから同時に開始する。

個別の非同期通知を待たず、監督プロセスが両方の状態を確認する。

両方が成功した場合は、二つの結果をClaudeへ返す。

片方だけが成功した場合は、成功結果を保持し、失敗側の診断情報とともに返す。

片方がタイムアウトしても、もう片方を自動キャンセルしない。

両方が `completed` または `failed` へ到達するか、それぞれの実行時間の上限へ達した時点でClaudeへ制御を戻す。

## 実行状態の保存

監督処理は実行ごとに一意なIDを発行する。

実行状態には、プロバイダー、モード、モデル、エフォート、PID、開始時刻、最終進捗時刻、終了状態、ログの場所を保存する。

子プロセスの標準出力と標準エラーをファイルへ保存し、完了通知を取りこぼした後でも結果を回収できるようにする。

保存先はGit管理外のユーザー状態ディレクトリとし、ディレクトリを所有者だけが参照できる権限で作成する。

状態ファイルとログには環境変数、認証情報、APIキーを記録しない。

プロンプト全文の永続保存は避け、タスクを識別できる短い要約だけを状態へ残す。

監督処理またはClaude Codeが中断した場合、`status` は保存済みのPID、終了状態、ログを使って状態を再判定する。

## エラー処理

監督処理は `success`、`partial`、`failed`、`timed_out`、`stale` を区別してClaudeへ返す。

返却値には、実行ID、各ジョブの状態、モデル、エフォート、終了コード、結果の場所、診断情報を含める。

出力が不正な場合は成功として扱わず、解析失敗と元の出力の場所を返す。

CodexまたはAntigravityが見つからない場合は、実行を開始せず、利用できないCLIと確認方法を返す。

モデルまたはエフォートが許可一覧にない場合は、子プロセスを起動せず入力エラーを返す。

## セキュリティ

監督処理は `--dangerously-bypass-approvals-and-sandbox`、`--dangerously-skip-permissions`、同等の権限回避オプションを組み立てない。

Codex実装では対象ワークスペースだけを書き込み可能にする。

Codexレビューは読み取り専用で実行する。

Antigravity検証はユーザーが指定したローカル開発環境とテスト用アカウントだけを対象にする。

本番URL、実アカウント、決済、外部データの変更は行わない。

監督処理は `git push`、デプロイ、サービス再起動を実行しない。

## テスト

新しい依存パッケージは追加せず、Node.js標準のテスト機能を使う。

外部プロセス、時刻、待機処理、ファイル状態はインタフェース経由でコンストラクタ注入する。

テストダブルにはMockではなく、次のFakeを使う。

- `FakeCodexProcess`
- `FakeAntigravityProcess`
- `FakeClock`
- `FakeSleeper`
- `InMemoryRunStateRepository`

テストでは次の振る舞いを保証する。

- 通知が届かなくてもCodexの完了結果を回収できる。
- CodexレビューとAntigravity検証を同時に開始する。
- 片方だけ失敗しても成功結果を保持する。
- Codexの無進捗が10分続くと `stale` を返す。
- タイムアウト後も子プロセスを自動終了しない。
- 保存済み状態から完了結果を再取得できる。
- 不正なモデルとエフォートを拒否する。
- 危険な権限回避オプションを組み立てない。
- ログへ認証情報と環境変数を書き出さない。

## chezmoiでの管理

`codex-advisor` のスキル本体、監督スクリプト、テストをchezmoiのソース状態へ追加する。

chezmoiから `~/.claude/skills/codex-advisor` へ反映できる構成にする。

既存のchezmoi未コミット変更には触れず、今回の変更だけを論理単位ごとにコミットする。

実装後もCAO設定は変更しない。

## 完了条件

次の条件をすべて満たした時点で実装完了とする。

- `advise`、`implement`、`review`、`verify-parallel`、`status` が動作する。
- 動的モデルルーティングが許可一覧どおりに動作する。
- Codexの完了通知を使わずに結果を回収できる。
- CodexレビューとAntigravity検証が並列に開始される。
- ハング疑いとタイムアウトがClaudeへ返り、自動キャンセルと自動再実行が行われない。
- Fakeを使った正常系、境界値、異常系のテストが通る。
- フォーマット、静的検査、テストが通る。
- chezmoiのソース状態と適用後のユーザー状態が一致する。
